# КАСТОМС ЛИДЕР — release candidate

Готовая к выкладке версия сайта. Пересобирается командой `npm run build:release`. Папка `site/` при этом создаётся заново, а этот файл и `nginx.conf.example` остаются.

## Что выкладывать

Содержимое папки `site/` копируется в корень сайта на хостинге (обычно `public_html/` или `www/`):

```
site/
├── index.html            страница сайта
├── assets/               скрипт, стили, шрифты, фото, PDF договора страхования
│                         (имена с хэшем: при изменениях меняется имя, кэш не мешает)
├── favicon-16x16.png
├── favicon-32x32.png
├── apple-touch-icon.png
├── safari-pinned-tab.svg
├── api/
│   ├── lead.php          приём заявок → Bitrix24
│   ├── config.example.php образец настроек (config.php создаётся на сервере)
│   └── .htaccess         закрывает настройки от доступа извне
├── robots.txt            индексация разрешена
└── .htaccess             кэш и сжатие для Apache (скрытый файл, не забудьте скопировать)
```

Сайт работает и в корне домена, и в подпапке: все пути относительные. `index.html` можно открыть и прямо с диска двойным кликом, чтобы посмотреть перед выкладкой.

## Сервер

- **Apache** (большинство виртуальных хостингов): настройки уже в `.htaccess`.
- **Nginx**: см. `nginx.conf.example`. `.htaccess` на nginx не действует, его можно не копировать.

Кэш: файлы из `assets/` кэшируются на год, `index.html` каждый раз проверяется заново, поэтому обновление сайта видно сразу.

## Приём заявок → Bitrix24

Формы отправляют заявки в `api/lead.php`, а он создаёт лид в Bitrix24. Нужен PHP 7.4 или новее (на cPanel он есть по умолчанию).

Один раз после первой выкладки:

1. В Bitrix24: **Разработчикам → Другое → Входящий вебхук**, права **CRM (crm)**. Скопируйте адрес вида `https://ваша-компания.bitrix24.ru/rest/1/abc123…/`.
2. В cPanel → **Диспетчер файлов** откройте `public_html/api/`, скопируйте `config.example.php` в `config.php`.
3. В `config.php` вставьте адрес вебхука в `bitrix24_webhook` и сохраните.
4. Отправьте тестовую заявку с сайта: в Bitrix24 появится лид «Заявка с сайта: …».

`config.php` в сборку не входит, поэтому при следующих выкладках не затирается. Не публикуйте адрес вебхука: с ним можно управлять CRM.

Если Bitrix24 не ответит, заявка уйдёт письмом на `fallback_email` из `config.php`. Если не сработает и это, посетитель увидит просьбу позвонить.

Защита от спама: скрытое поле-ловушка для ботов, приём только со страниц своего сайта, не больше 5 заявок с одного адреса за 10 минут.

## Чего в сборке нет (намеренно)

- Страница настроек `3d.html` и 3D-сцены (Three.js): на сайте используются фото.
- Сборка в один HTML-файл (`docs/`, для GitHub Pages и презентаций).
